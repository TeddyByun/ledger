# 금월 예상 소비 지출 예측 · 정기지출 관리 — 설계

## 1. 목표

- **금월(이번 달) 및 향후 달의 예상 총지출**을 이력 기반 **규칙 엔진**으로 예측한다.
- 예측의 재료인 **매월 반복되는 지출(정기지출)** 을 자동 추천하고, 사용자가
  **체크(포함)/해제(제외)/직접 추가** 할 수 있게 한다.

## 2. 예상 총액의 뼈대

한 대상월 `YM` 의 예상 지출은 **버킷별 규칙 예측의 합 + 잔여 변동**이다.

```
예상 지출(YM)
  = Σ 규칙별 예측(YM)         -- R1~R5 (+제안 규칙): 정기/스케줄/계절성 등
  + 잔여 변동지출(YM)          -- 위 규칙이 가져가지 않은 나머지: 최근 N개월 평균
```

- **이번 달**은 여기에 "이미 발생한 실지출"을 반영: 규칙 예측 중 **이미 발생분은
  실제 금액으로 대체**하고 **미발생분만 예측**으로 더한다(§5 매칭).
- 집계제외 분류·이체/카드대금(exclude_reason)은 **모든 계산에서 제외**.
- 금액 기준 = `transaction.amount`(할부는 회차 결제액 등 실지출).

화면 분해(이번 달): **① 이미 지출(A)** + **② 남은 정기·스케줄(B)** + **③ 예상 변동(C)**.

## 3. 예측 규칙 엔진 (핵심)

### 3.1 지출을 "버킷"으로 나눠 규칙을 배정 — 중복 계산 방지

같은 지출이 두 규칙에 잡히면 이중 계산된다. 그래서 **각 지출(분류·항목)을 정확히
한 규칙에만** 배정한다. 우선순위(위 → 아래):

| 순위 | 규칙 | 대상 버킷 | 성격 |
|---|---|---|---|
| 1 | **R3 할부** | 진행 중 할부 | 스케줄 확정 |
| 2 | **R7 확정 스케줄** | 대출 원리금·정기적금·리볼빙 (만기월까지) | 스케줄 확정 |
| 3 | **R4 반복 고정** | 구독·월세·보험·통신 등 사용자 확정 정기지출 | 월 정액 |
| 4 | **R6 연례/비월별**(제안) | 자동차세·재산세·연회비·명절 등 | 연 1~2회 |
| 5 | **R2 공과금** | 대분류 04(전기·가스·수도·관리비 등) | 매월·계절성 |
| 6 | **R1 경조사** | 대분류 10(경조사) | 비정기·연중 특정월 |
| 7 | **R5 계절성/추세** | 그 외 매월 발생 + 계절/추세 있는 분류 | 매월·가변 |
| 8 | (나머지) **잔여 변동** | 위에 안 잡힌 생활성 지출 | 최근 N개월 평균 |

- 배정 단위는 **분류(대분류) 또는 항목(match_key)**. 한 분류 안에서도 특정 항목을
  R3/R4가 가져가면 그 항목은 이후 규칙·변동평균에서 뺀다.
- **버킷 배정표**는 forecast 계산 시 매번 산출(항상 최신). 사용자 확정 정기지출은
  버킷을 고정(잠금)한다.

### 3.2 규칙별 상세

각 규칙 = { 대상, 데이터 창(window), 대상월 예측 산출식, 발생월 판정, 신뢰도, 근거 }.

#### R1. 경조사 — 과거 1년, 연중 특정월 패턴
- **대상**: 대분류 `10 경조사`(비정기·계절 발생: 결혼 5·10월, 명절, 부고 등).
- **창**: 과거 **1년**(권장 2년, 있으면 사용).
- **산출**: 달(月, 1~12)별 발생액을 집계 → 대상월의 **과거 같은 달 평균(또는 중앙값)**.
  발생 이력이 없는 달은 0. (매월이 아니라 **그 달에만** 예측을 얹음)
- **신뢰도**: 표본이 적어 낮음 → 점추정 + 범위(§3.4).
- **근거**: "최근 1년 중 5월 2건 평균 20만".

#### R2. 공과금 — 과거 1년, 매월·계절성
- **대상**: 대분류 `04 공과금·주거` 중 **매월 발생**하는 소분류(관리비·전기·가스·수도).
- **창**: 과거 **1년**.
- **산출**: 소분류별로 **전년 동월값**(냉난방 계절성 반영)을 기준으로,
  최근 3개월 추세로 보정. 전년 동월 없으면 최근 3개월 평균.
- **발생월 판정**: 매월 발생 → 이번 달 미발생이면 예측 가산, 발생이면 실제값 사용.
- **근거**: "전년 7월 전기료 9.2만 → 올 7월 예측".

#### R3. 할부 — 과거 1개월(최신 명세) 참조, 만기월까지 확정 가산
- **대상**: 진행 중 할부(`installment_plan`, 또는 `card_transaction.billing_round <
  installment_period`). 남은 회차 = `total_months − 현재 회차`.
- **창**: **최근 1개월** 명세로 "현재 몇 회차/남은 회차"를 파악.
- **산출**: 각 할부의 **회차 결제액(원금+수수료)** 을 **만기월까지 각 달에 확정 가산**.
  (미래 달엔 아직 `transaction`이 없으므로 이 규칙이 그 자리를 채움)
- **신뢰도**: **높음(확정 스케줄)**.
- **중복 방지**: 과거·이번 달 이미 발생한 회차는 실지출(A)에 이미 있으니 **미래 회차만** 예측.

#### R7. 대출 상환·정기적금·리볼빙 — 만기월까지 확정 스케줄
- **대상**: 대분류 `01 대출`(원리금 상환), `02 투자·저축`의 **정기적금(0202)**, 리볼빙 등
  **매월 정액이 만기까지 이어지는** 항목. (할부 R3와 형제 — 차이는 만기 정보의 출처)
- **창**: 과거 1년(반복·금액 탐지) + **만기 정보**.
- **만기 해석(우선순위)**:
  1. **데이터에 만기/스케줄이 있으면 참고** (예: 할부성으로 잡히면 `total_months`).
  2. 없으면 **사용자가 입력한 만기 년월(`end_ym`)** 사용.
  3. **둘 다 없으면 "만기 미설정"** → 관리 화면에서 **만기 년월 입력을 유도**(경고 뱃지).
     입력 전까지는 **이번 달만** 예측(미래로 무기한 확산 금지)해 과대예측을 막는다.
- **산출**: 월 정액을 `start_ym ~ end_ym` 각 달에 가산. 대상월 `> end_ym` → 0(만기 후 종료),
  `≤ end_ym` → 예측 가산. 이번 달 이미 발생분은 실지출(A)로 대체(§5).
- **신뢰도**: 만기·금액 확정 시 **높음**, 만기 미설정 시 **중**.
- **근거**: "정기적금 30만 · 만기 2027-05(잔여 10개월)", "주택대출 원리금 98만 · 만기 2038-03".

> 적금은 지출(내 돈이 적금계좌로 나감)로 다루되, 집계 성격에 맞게 분류(02 투자·저축)로
> 예측한다. 대출·적금 모두 **만기 도래 시 예측에서 자동 종료**된다.

#### R4. 반복 고정지출 — 과거 1년, 매월 정액
- **대상**: 매월 거의 같은 금액으로 반복(구독·월세·보험·통신·대출상환·정기적금).
- **창**: 과거 **1년**.
- **탐지**: `fuzzyKey(내용) + 대분류` 로 그룹화(끝 숫자 제거해 `METLIFE06193/05192`를
  한 항목으로 — 기존 `fuzzyKey` 재사용) → 최근 6개월 중 **≥3개월** 등장 + 금액 안정.
  예상금액 = 최근 3개월 **중앙값**. → **추천**으로 노출, 사용자 체크 시 확정 저장.
- **산출**: 활성 정기지출의 예상금액을 대상월에 가산(이번 달 미발생분만).
- **근거**: "최근 6개월 중 6개월, 월 17,000".

#### R5. 계절성·추세 — 과거 3년, 매월·규칙적 증감
- **대상**: 매월 발생하나 **금액이 계절/추세로 변하는** 분류(위 R1~R4·R6가 안 가져간 것).
- **창**: 과거 **3년**(부족하면 가용 연수로 자동 축소).
- **산출**: 분류별 월 시계열에서
  1) **계절지수** = 월별 평균 ÷ 전체 평균 (예: 여름 냉방·명절 소비),
  2) **추세율** = 연도별 증감(물가·소비 변화),
  → 예측 = `최근수준 × 계절지수(대상월) × (1 + 추세율)`.
- **신뢰도**: 3년 있으면 중, 부족하면 낮음 → 범위 표기.
- **근거**: "3년 평균 대비 7월 계절지수 1.2, 추세 +4%/년".

### 3.3 추가 제안 규칙 (검토 요청)

- **R6. 연례/비월별 주기지출**: 자동차보험 갱신·자동차세·재산세·연회비·명절(설·추석)·
  종합소득세 등 **연 1~2회 정해진 달**에 발생. 과거 1~2년의 **발생 월**을 참조해 해당
  월에만 예측. (R1과 유사하나 "정례"라 더 확정적. `recurring_expense.cadence=annual`.)
- **R7. 확정 스케줄(대출·적금·리볼빙)** → **본문 3.2로 승격(확정)**. 만기 있으면 참고,
  없으면 만기 년월 입력.
- **R8. 신규/해지 감지**: 최근 새로 시작한 반복 항목(구독 등록)은 이력이 짧아도 **이달부터
  포함**, 최근 **3개월 연속 미발생** 항목은 **해지로 간주해 예측에서 제외**.
- **R9. 이상치(일회성 대형지출) 제거**: 가전 구매·큰 의료비 등 **일회성 스파이크**는
  변동 평균·계절성 계산에서 제외해 **과대예측 방지**(예: 상위 분위수 컷 또는 중앙값 사용).
- **R10. 예측 범위(불확실성)**: 점추정만이 아니라 **하한~상한**(±표준편차 또는 분위수)로
  "예상 15만~22만"처럼 제시.
- **R11. 수입 예측(선택)**: 급여 등 정기 **수입**도 같은 방식으로 예측해 **예상 잔액
  (수입−지출)** 까지 보여줄 수 있음. (이번 요구는 지출이지만 확장 여지.)
- **R12. 신뢰도·근거 표기**: 모든 예측 항목에 **근거(참조 개월/연수, 편차)** 와
  **신뢰 등급(높음/중/낮음)** 을 붙여 왜 그 값인지 설명.

### 3.4 합성·신뢰도

- **총 예측** = Σ(각 버킷의 대상월 예측). 잔여(어느 규칙도 안 가져간 생활성 지출)는
  **최근 N개월(기본 3) 변동 평균**. 이번 달은 "이미 쓴 변동 + 남은 변동(=max(0, 평균−실지출))".
- 데이터 부족 시 **자동 강등**: 3년 없으면 가용 연수, 1년 없으면 있는 만큼, 표본 1~2개면
  신뢰도 '낮음' + 범위 넓힘.
- 각 규칙 결과에 `confidence`(high/med/low)와 `basis`(근거 문자열)를 부여해 화면에 노출.

`recurring_expense` — 사용자 확정 정기/연례 지출(체크 상태 보관). 추천 후보는 미저장(매번 계산).

| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | Int PK | |
| household_id | Int | 가구 스코프 |
| label | String | 표시명 |
| category_code | String FK | 분류 |
| payment_method_id | Int? FK | 결제수단(선택) |

| source | enum(auto, manual) | 추천 확정 / 수기 |

| created_at / updated_at | | |

- 할부(R3)·스케줄(R7)은 **기존 `installment_plan` / `transaction` 이력에서 계산**하므로

- 인덱스: `@@index([household_id, is_active])`, `@@index([household_id, category_code])`.

## 5. 이번 달 발생 매칭 (실지출 우선)

- 이번 달 지출 `transaction` 중 `fuzzyKey(description)==match_key`(+결제수단 일치) 건이
  있으면 **그 항목은 발생함** → 예측 대신 **실제 금액**을 A에 반영, B에서 제외.
- 없으면 미발생 → 예상금액을 B(남은 정기·스케줄)에 가산. 예상일이 지났으면 '지연', 아니면 '예정'.

## 6. 화면 (배치 확정)

### 6.1 `집계 > 예상 지출` (신규) — 예측 요약
- **예상 총지출** 큰 숫자 + 지난달 실지출 대비(±%), **예측 범위(하한~상한)**.
- **A/B/C 분해 막대**(이미 지출 / 남은 정기·스케줄 / 예상 변동).
- **규칙별 기여 목록**: 항목·분류·예측액·근거·신뢰도(예: "전기료 9.2만 · 전년동월 · 높음").
- 경과일 게이지, "정기지출 관리" 링크.

### 6.2 `관리 > 정기지출` (신규) — 추천/설정
- **추천 섹션**(R4·R6·R7 후보): 체크박스 목록(표시명·분류·예상금액·주기·근거). 체크→확정.
- **내 정기지출**: 활성 토글(=체크), 금액·주기·예상일·분류 수정, 삭제, **+ 직접 추가**.
- **대출·적금(R7, cadence=schedule)**: **만기 년월(`end_ym`) 입력란** 제공.
  - 데이터로 만기를 알 수 있으면 자동 채우고, 없으면 사용자가 입력.
  - **만기 미설정이면 "만기 입력 필요" 경고 뱃지** + 잔여 개월수(만기까지) 표시.
- 발생 상태 뱃지(발생·예정·지연). 할부(R3)는 자동 계산분을 **읽기 전용 참고**로 표시.

## 7. API (신규)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/stats/forecast?ym=YYYY-MM` | 예상 총지출 + A/B/C + 규칙별 기여 + 범위 |
| GET | `/recurring-expenses` | 확정 정기지출(이번 달 상태 포함) |
| POST/PATCH/DELETE | `/recurring-expenses[/:id]` | 추가/수정/삭제·토글 |
| GET | `/recurring-expenses/suggestions` | R4·R6·R7 추천 후보(대출·적금 포함)(미등록만) |

- 모두 가구 스코프. forecast 는 `transaction`+`installment_plan`+`recurring_expense`에서
  직접 계산(사전집계 불필요, 항상 최신).

## 8. 구현 계획

1. 스키마·마이그레이션(`recurring_expense`, enum).
2. 규칙 엔진 서비스: 버킷 배정 → R3/R7(스케줄) → R4/R6(정기·연례) → R2(공과금) →
   R1(경조사) → R5(계절성) → 잔여 변동평균. `confidence/basis` 부여.
3. 추천(suggestions) + 정기지출 CRUD API.
4. `forecast(ym)` API(A/B/C·규칙별 기여·범위) + 이번 달 매칭.
5. 프론트: 정기지출 관리 화면 → 예상 지출 화면.
6. 검증(규칙별 합 = 총액, 할부 만기월 정확, 계절지수 sanity) → 커밋.

## 9. 결정 완료 / 기본 파라미터

- **변동 예측 = 최근 N개월 평균**(기본 N=3, 완료된 달).
- **배치**: 예측=`집계 > 예상 지출`, 관리=`관리 > 정기지출`.
- **규칙 창**: R1 1년 · R2 1년 · R3 최근 1개월 · R4 1년 · R5 3년 · **R7 1년+만기정보**
  (부족 시 자동 축소).
- **R7(대출·적금) 확정 채택**: 만기 있으면 참고, 없으면 만기 년월 입력. 만기 도래 시 자동 종료.
- **탐지 기본**: 최근 6개월 중 ≥3개월, 예상=중앙값, 그룹키=fuzzyKey+대분류.
- **제안 규칙 R6~R12**는 사용자 채택 여부 확인 후 반영.
