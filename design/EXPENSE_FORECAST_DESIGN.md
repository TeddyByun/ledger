# 금월 예상 소비 지출 예측 · 정기지출 관리 — 설계

## 1. 목표

- **금월(이번 달) 예상 총지출**을 예측해 보여준다.
- 예측의 핵심 재료인 **매월 반복되는 지출(정기지출)** 을 이력에서 **자동 추천**하고,
  사용자가 **체크(포함)/해제(제외)** 하거나 **직접 추가·수정**할 수 있게 한다.
- "체크가 안 된(=추천됐지만 아직 확정 안 한, 또는 자동 탐지 안 된) 항목을 설정" 하는
  관리 화면을 제공한다.

## 2. 개념 정의

이번 달 예상 총지출을 **정기 + 변동** 두 축으로 나눠 계산한다.

| 구분 | 정의 | 예 |
|---|---|---|
| **정기지출(fixed)** | 매월 거의 같은 금액으로 반복되는 지출 | 월세, 통신비, 보험, 구독, 대출상환, 정기적금 |
| **변동지출(variable)** | 그 외 비정기 생활 지출 | 외식, 마트, 주유, 쇼핑 |

- **집계제외 분류·이체/카드대금(exclude_reason)** 은 예측에서 제외(기존 규칙과 동일).
- 금액은 `transaction.amount`(할부는 회차 결제액 등 실지출) 기준.

### 예상 총지출 공식

```
예상 총지출(이번 달)
  = 이번 달 실지출(오늘까지)                       -- (A) 확정
  + 남은 정기지출(활성 정기지출 중 이번 달 미발생분) -- (B) 예정
  + 예상 잔여 변동지출                              -- (C) 예측
```

- **(A) 실지출**: 이번 달 `transaction` 지출 합(집계제외·이체 제외).
- **(B) 남은 정기지출**: 활성 정기지출 각각에 대해 "이번 달에 이미 발생했는가?"를
  매칭으로 판정 → **미발생분의 예상금액만** 더한다. (이미 발생분은 A에 이미 포함)
- **(C) 예상 잔여 변동지출** — **확정: 최근 N개월 평균 방식** (진행률 아님).
  - `변동_월평균` = 최근 **N개월(기본 3, 완료된 달)** 의 변동지출 평균
    (= 각 달 지출 − 그 달 정기 발생분 − 집계제외).
  - (C) = `max(0, 변동_월평균 − 이번달_변동_실지출)`
    (이미 평균을 넘겼으면 잔여 0 → 총액은 실지출을 따라감).
  - 요약하면 **예상 변동 총액 = max(이번달 변동 실지출, 변동_월평균)**.

> 화면에는 **① 예상 총액 하나의 큰 숫자**와 **② A/B/C 분해 막대**,
> **③ 지난달 대비**를 함께 보여준다.

## 3. 데이터 모델 (신규)

`recurring_expense` — 확정된 정기지출. (추천 후보는 저장하지 않고 매번 계산)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | Int PK | |
| household_id | Int | 가구 스코프(미들웨어 자동 주입) |
| label | String | 표시명 (예: "넷플릭스", "월세", "METLIFE 보험") |
| category_code | String FK→category | 분류(대/소분류) |
| payment_method_id | Int? FK | 결제수단(선택; 매칭 정밀도↑) |
| amount | Decimal(15,2) | 이번 달 예상 금액(월 고정액) |
| day_of_month | Int? (1–31) | 예상 청구일(선택; 미발생 판정·표시용) |
| match_key | String? | 자동 매칭 키(내용 fuzzyKey). 실거래↔정기지출 연결 |
| source | enum(auto, manual) | 추천에서 확정 / 수기 추가 |
| is_active | YesNo (Y/N) | **체크 상태 = 예측에 포함 여부** |
| memo | String? | |
| created_at / updated_at | | |

- `@@index([household_id, is_active])`, `@@index([household_id, category_code])`
- **"체크"의 실체 = `is_active`**. 추천을 체크하면 `is_active='Y'`로 저장,
  해제하면 `'N'`(또는 미저장). 수기 항목도 동일 토글.

> 후보(추천)를 DB에 저장하지 않는 이유: 이력이 바뀌면 후보도 바뀌므로
> **확정된 것만** 저장해 사용자 통제 하에 둔다. (분류 자동추천과 동일 사상)

## 4. 정기지출 자동 추천 (탐지)

최근 **N개월(기본 6)** 지출 `transaction`을 스캔해 반복 후보를 만든다.

1. **그룹 키** = `fuzzyKey(description)` + `category_code`(대분류)
   - `fuzzyKey`는 끝 숫자를 떼어 `METLIFE06193/05192`를 한 그룹으로 묶음(기존 함수 재사용).
   - 결제수단까지 같이 묶을지는 선택(정밀도 vs 과분할).
2. **반복성 판정**: 최근 N개월 중 **≥ K개월(기본 3)** 에 등장.
3. **금액 안정성**: 월별 금액의 변동계수가 작으면 "고정액", 크면 "변동형 정기"(예상금액=중앙값).
4. 후보에 **예상금액=최근 3개월 중앙값**, **예상일=최빈 청구일**, **최근 발생월**을 부여.
5. 이미 `recurring_expense`로 등록된 그룹(match_key 일치)은 후보에서 제외(중복 방지).

→ 관리 화면에서 후보를 **체크박스 목록**으로 노출. 체크 시 `recurring_expense`로 확정 저장.

## 5. 이번 달 발생 여부 매칭 (B 계산)

활성 정기지출이 "이번 달에 이미 나갔는지" 판정:

- 이번 달 지출 `transaction` 중 `fuzzyKey(description)==match_key`
  (그리고 payment_method_id 지정 시 일치)인 건이 있으면 **발생함** → B에 미포함.
- 없으면 **미발생** → 예상금액을 B에 가산. (예상일이 지났으면 "지연", 안 지났으면 "예정")

## 6. 화면(UI)

### 6.1 예측 요약 — 신규 메뉴 `집계 > 예상 지출`
- 구성:
  - 큰 숫자: **예상 총지출** + 지난달 실지출 대비(±%).
  - 분해 막대: **이미 지출(A) / 남은 정기(B) / 예상 변동(C)** 3분할.
  - 진행 게이지: 이번 달 경과일 / 총일수.
  - 하단: "정기지출 관리" 링크.

### 6.2 정기지출 관리 — 신규 메뉴 (`관리 > 정기지출`)
- **추천 섹션**: 자동 탐지 후보 목록.
  - 각 행: 체크박스 | 표시명 | 분류 | 예상금액 | 예상일 | 최근 발생월 | (근거: "최근 6개월 중 5개월")
  - 체크 → 확정(`recurring_expense` 생성, `is_active='Y'`).
- **내 정기지출 섹션**: 확정된 항목 목록.
  - 활성 토글(체크=예측 포함), 금액·예상일·분류 수정, 삭제.
  - **+ 직접 추가**: 추천에 없는 정기지출을 수기로 등록.
- 이번 달 발생/미발생 상태 뱃지(발생·예정·지연) 표시.

## 7. API (신규)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/recurring-expenses` | 확정 정기지출 목록(이번 달 발생상태 포함) |
| POST | `/recurring-expenses` | 정기지출 추가(수기 또는 추천 확정) |
| PATCH | `/recurring-expenses/:id` | 금액·예상일·분류·활성 토글 수정 |
| DELETE | `/recurring-expenses/:id` | 삭제 |
| GET | `/recurring-expenses/suggestions` | 이력 기반 추천 후보(미등록만) |
| GET | `/stats/forecast?ym=YYYY-MM` | 예상 총지출 + A/B/C 분해 + 지난달 대비 |

- 모두 가구 스코프 미들웨어 적용. `stats/forecast`는 `transaction` +
  `recurring_expense`에서 직접 계산(사전집계 불필요, 항상 최신).

## 8. 단계별 구현 계획

1. **스키마·마이그레이션**: `recurring_expense` 테이블 + enum(`RecurringSource`).
2. **탐지 서비스**: `suggestions()` (fuzzyKey 그룹화·반복성·중앙값).
3. **CRUD API**: recurring-expenses 컨트롤러/서비스/DTO.
4. **예측 서비스**: `forecast(ym)` (A/B/C, 매칭, run-rate).
5. **프론트 — 정기지출 관리 화면**: 추천 체크·내 목록·수기 추가.
6. **프론트 — 예상 지출 카드**: 요약 + 분해 막대.
7. 검증(실데이터로 A+B+C 합·매칭 정확도) → 커밋.

## 9. 결정 완료 / 기본 파라미터

- **변동지출 예측 = 최근 N개월 평균**(§2 C). 기본 N=3(완료된 달).
- **배치**: 예측 요약 = `집계 > 예상 지출`(신규), 정기지출 관리 = `관리 > 정기지출`(신규).
- **탐지 기본값**(조정 가능): 최근 6개월 중 ≥3개월 등장, 예상금액=최근 3개월 중앙값,
  그룹키 = `fuzzyKey(내용) + 대분류`.
- 집계제외 분류·이체/카드대금은 예측·평균 계산에서 제외.
